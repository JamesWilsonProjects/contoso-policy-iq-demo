Step 1 of 4 · Document Repository

Upload Raw Policy Docs to Azure Blob Storage

Start with standard Azure Blob Storage (or ADLS Gen2). Drop your existing Word, PDF, or Markdown policy documents into a container—no pre-processing needed.

📦 What You Configure in Azure Storage

  • Storage Account: Standard GPv2 or ADLS Gen2 with blob container (e.g., corporate-policies).
  • Supported File Formats Out-of-the-Box: .pdf, .docx, .pptx, .xlsx, .md, .html, .txt, .json.
  • Optional Blob Metadata: Tag blobs with metadata attributes (e.g., department=HR, effective_date=2026-01-01) if you want filterable metadata columns automatically carried into the index.
  • Passwordless Auth (Recommended): Enable System-Assigned Managed Identity on your Azure AI Search service and assign it the Storage Blob Data Reader RBAC role on the storage account.
# 1. Upload your raw Word / PDF / Markdown policy files az storage blob upload-batch \ --account-name stcontosopolicies \ --destination corporate-policies \ --source ./policies/ \ --auth-mode login # 2. Grant Azure AI Search Managed Identity read access az role assignment create \ --role "Storage Blob Data Reader" \ --assignee-object-id <SEARCH_MANAGED_IDENTITY_PRINCIPAL_ID> \ --scope /subscriptions/<SUB_ID>/resourceGroups/<RG>/providers/Microsoft.Storage/storageAccounts/stcontosopolicies
Enterprise Tip: Also works with SharePoint Online (remoteSharePoint) and Microsoft Fabric OneLake (indexedOneLake) knowledge sources.

Step 2 of 4 · Automated Vectorization Pipeline

Point Foundry IQ at Your Blob Container (azureBlob)

When you create a Knowledge Source with "kind": "azureBlob" (in the Foundry Portal or via REST), Azure AI Search automatically builds and runs the entire ingestion & vectorization pipeline for you.

⚡ 4 Resources Auto-Provisioned Behind the Scenes

  • 1. Managed Data Source: Connects to your corporate-policies Blob container with high-water-mark change tracking and soft-delete detection.
  • 2. Managed Skillset (Chunking + Embedding):
    • Cracks PDFs / Word docs and extracts text & tables.
    • Runs the Text Split Skill to chunk documents into semantic passages.
    • Calls Azure OpenAI text-embedding-3-small (or 3-large) to vectorize every chunk.
  • 3. Managed Search Index: Configured with HNSW vector search, an integrated query-time vectorizer, BM25 keyword fields, and a Semantic Ranker configuration.
  • 4. Managed Indexer: Runs immediately and on a recurring schedule to keep the index in sync when blobs are added or updated.
// PUT https://<search>.search.windows.net/knowledgesources/contoso-blob-ks?api-version=2026-08-01-preview { "name": "contoso-blob-ks", "kind": "azureBlob", "description": "Corporate HR, Leave, and Travel policies in Blob Storage", "azureBlobParameters": { "connectionString": "ResourceId=/subscriptions/.../storageAccounts/stcontosopolicies;", "containerName": "corporate-policies", "ingestionParameters": { "embeddingModel": { "kind": "azureOpenAI", "azureOpenAIParameters": { "resourceUri": "https://demo-newfoundry-resource.openai.azure.com", "deploymentId": "text-embedding-3-small", "modelName": "text-embedding-3-small" } }, " ingestionSchedule": { "interval": "PT1H" } } } }
What About Query Time? Because the auto-created index includes an Integrated Vectorizer, incoming user subqueries are also vectorized automatically inside Azure AI Search.

Step 3 of 4 · Agentic Retrieval Engine

Create the Foundry IQ Knowledge Base (contoso-policy-kb)

Traditional single-query RAG fails when an employee asks a multi-part question (e.g., "Compare Standard vs. Las Vegas vs. NYC hotel caps, meal limits, and receipt rules"). The Foundry IQ Knowledge Base solves this with LLM-driven query planning.

🧠 What the Knowledge Base Does on Every Query

  • 1. Subquery Decomposition: Uses gpt-4.1 + your retrievalInstructions to break a complex prompt into 3–9 targeted subqueries in parallel.
  • 2. Parallel Hybrid + Vector Search: Executes BM25 keyword + text-embedding-3-small HNSW vector search across contoso-blob-ks for every subquery simultaneously.
  • 3. L2 Semantic Reranking: Scores and deduplicates candidate passages (0.00 – 4.00 semantic score) and selects the highest-signal policy chunks.
  • 4. Native MCP Server Endpoint: Automatically exposes an MCP endpoint (/knowledgebases/contoso-policy-kb/mcp) with the knowledge_base_retrieve tool ready for any Foundry Agent.
// PUT https://<search>.search.windows.net/knowledgebases/contoso-policy-kb?api-version=2026-08-01-preview { "name": "contoso-policy-kb", "outputMode": "extractiveData", "retrievalInstructions": "Decompose multi-part or comparative policy questions into targeted subqueries across the Contoso policy knowledge source...", "knowledgeSources": [ { "name": "contoso-blob-ks" } ], "models": [ { "kind": "azureOpenAI", "azureOpenAIParameters": { "resourceUri": "https://demo-newfoundry-resource.openai.azure.com", "deploymentId": "gpt-4.1", "modelName": "gpt-4.1" } } ] }
Multi-Source Federation: A single Knowledge Base can query multiple Knowledge Sources at once (e.g., azureBlob + remoteSharePoint + searchIndex).

Step 4 of 4 · Agent Orchestration & Compliance

Connect Microsoft Foundry Agent & Multi-Layer Guardrails

Finally, connect your Microsoft Foundry Agent to the Knowledge Base via a Project MCP Connection and enforce defense-in-depth PII/PHI and grounding guardrails.

🔌 1. Foundry MCP Connection

  • Create a RemoteTool MCP connection in your Foundry Project pointing to .../knowledgebases/contoso-policy-kb/mcp.
  • Uses ProjectManagedIdentity with audience https://search.azure.com (zero API keys stored).
  • Works with both declarative Prompt Agents and custom Python Hosted Code Agents.

🛡️ 2. PII & PHI Guardrails

  • Layer 1 Pre-Flight Gate: Fast deterministic/regex + PHI scanner blocks SSNs, Credit Cards, Bank Accounts, Employee IDs, and Medical Diagnoses in 2 ms (0 tokens) and offers one-click redaction.
  • Layer 2 Foundry Native RAI Policy: Attach contoso-policy-pii-guardrail at the Azure AI Foundry gateway to enforce platform-level PII & Jailbreak blocking.

📌 3. Closed-World Grounding

  • System prompt enforces strictly extractive facts with temperature=0.0 and no web search tool enabled.
  • Requires inline citations (【DOC_ID†Section】) on every claim, dollar threshold, and approval rule.
  • Explicitly refuses out-of-scope benefits traps (e.g., gym stipends, pet bereavement, Tokyo hotel caps).
Low Perceived Latency: Stream intermediate SSE events (guardrail → retrieval → token-by-token delta) so users see progress immediately.

Architectural Comparison

Path 1 (azureBlob) vs. Path 2 (searchIndex)

Customers often ask: "When should we let Foundry IQ ingest directly from Blob Storage (Path 1) versus pushing chunks into our own Azure AI Search index (Path 2)?" Both plug into the exact same Foundry IQ Knowledge Base.

Dimension Path 1: Managed Blob Ingestion (kind: "azureBlob") Path 2: Bring-Your-Own Index (kind: "searchIndex")
How Ingestion Works Drop raw .pdf, .docx, or .md files in Azure Blob Storage. Foundry IQ auto-creates the Data Source, Skillset, Indexer, and Index. Your ingestion script or pipeline parses documents, computes embeddings, and pushes chunks into an Azure AI Search index.
Chunking & Vectorization Managed automatically via Azure AI Search Text Split Skill + AzureOpenAIEmbeddingSkill. Full custom control (e.g., splitting strictly on Markdown ## Section headings so financial tables are never split mid-row).
Ongoing Document Sync Built-in scheduled Indexer automatically detects new, modified, or deleted blobs in Storage. Triggered by your CI/CD pipeline, Event Grid trigger, or custom ingestion job.
Downstream Foundry IQ & Agent Experience Identical: Subquery planning, L2 semantic reranking, and MCP endpoint work the same way. Identical: Subquery planning, L2 semantic reranking, and MCP endpoint work the same way.
Best For 90% of enterprise deployments—turnkey ingestion over large PDF/Office repositories in Blob Storage, SharePoint, or OneLake. Specialized schemas, custom heading/table chunkers, or connecting an existing production Azure AI Search index to Foundry IQ.
Best of Both Worlds: You can start with Path 1 (azureBlob) in 10 minutes, and add custom searchIndex or remoteSharePoint sources to the same Knowledge Base anytime.

Customer Action Plan

5-Step Checklist to Deploy in Your Azure Tenant

Everything shown in this demo runs on standard Azure PaaS services using Entra ID Managed Identities (zero hardcoded keys).

1️⃣ Provision Core Resources

  • Microsoft Foundry Resource & Project with gpt-4.1 and text-embedding-3-small deployments.
  • Azure AI Search (Basic or Standard tier) with Semantic Ranker enabled.
  • Azure Storage Account (Blob container for policy docs).

2️⃣ Configure Entra ID RBAC

  • Search MI → Storage: Storage Blob Data Reader
  • Search MI → Foundry: Cognitive Services OpenAI User (for integrated vectorization & query planning)
  • Foundry Project MI → Search: Search Index Data Reader & Search Service Contributor

3️⃣ Wire Foundry IQ & Guardrails

  • Create Knowledge Source (azureBlob) + Knowledge Base (extractiveData).
  • Attach Foundry RAI Policy (UsSocialSecurityNumber, CreditCardNumber, PhoneNumber, EmailAddress, Prompt Shields).
  • Connect Agent via MCP & enable SSE streaming in your web/Teams frontend.
